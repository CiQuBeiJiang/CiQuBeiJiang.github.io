# CABNGIS：预算受限下的光储充协同调度搜索

!!! abstract "项目摘要"

    **CABNGIS**（Constraint-Aware Budgeted Neighborhood-Guided Iterative Search，约束感知预算化邻域引导迭代搜索）研究的是这样一个问题：在光伏 + 储能 + 电动车充电的家庭微网里，候选调度方案很便宜就能生成，但每一次**精确评估**（解一次储能 QP）都要花预算。那么，**应该先精确评估哪些候选？**

    核心做法是用"约束感知"的排序代替单纯按目标值排序：先看候选会不会让储能越界、离边界有多近、离可行域有多远，再看目标值。

    **结论（经过审计后的版本）**：约束感知排序能让接近最优的解**更早出现**（91 天 × 10 个种子的主实验中，71 天更快，Wilcoxon $p<10^{-10}$），但**不能稳定减少总评估次数或运行时间**。早期"比 SG-LNS 少 49% 评估次数"的说法，在统一停止规则后被推翻并撤回。

## 1. 问题定义

### 1.1 系统与决策变量

一天被切成 $T=12$ 个时段（每段 2 小时）。一个候选方案写作 $z=(s,\delta)$：

- $s_t\in\{1,2,3\}$：给每个时段打上 **谷 / 平 / 峰** 标签；
- $\delta\in\mathbb{R}^3$：分别控制 峰→谷、峰→平、平→谷 三个方向转移多少负荷，经过线性映射与截断变成转移比例 $\alpha\in[0,0.3]$。

$(s,\delta)$ 共同决定一条充电引导曲线 $p_{\text{guide}}$：负荷在不同类别的时段间搬移，再投影回单纯形以保证总需求不变。

![图 1　光储充系统结构：光伏出力、储能 SOC 约束、原始充电需求与分时电价共同决定调度](/optimization/images/cabngis/fig01-system.png)

### 1.2 下层：储能精确子问题

给定 $p_{\text{guide}}$，储能怎么充放由一个 QP 精确求解（Gurobi）：

- 储能功率 $P_{\text{net}}\in[-2000,2000]$ W，SOC $\in[0,5000]$ Wh，满足 SOC 递推；
- 购电 $P_{\text{buy}}\ge$ 净负荷，峰值 $P_{\text{peak}}$ 约束所有时段的购电。

目标函数是三项归一化指标之和（都除以"不做任何控制"时的值，越小越好）：

$$
q = \frac{\overline{P_{\text{net-load}}^2}}{f_1^{\text{base}}}
  + \frac{\sum_t c_t P_{\text{buy},t}\Delta t}{f_2^{\text{base}}}
  + \frac{P_{\text{peak}}}{f_3^{\text{base}}}
$$

分别对应 **净负荷波动、分时电价成本、峰值购电**。分时电价 $c_t$ 在 0.30 到 0.80 之间。

!!! note "问题的关键"

    生成候选几乎不花钱，真正贵的是精确评估。所以研究问题不是"怎么找到更好的解"，而是**在固定预算 $B$ 下，按什么顺序把候选送去精确评估**。

## 2. 算法流程

主循环在 `neural_lns_consolidated.run_neural_lns` 里，大致分五步：

![图 2　CABNGIS 主循环：由精英档案生成候选邻域，按优先级选出前若干个候选送入精确评估，再更新档案](/optimization/images/cabngis/fig02-loop.png)

1. **初始化**：用一批结构化模板（全峰、全平、全谷、光伏匹配、电价最优等，加上扰动和随机解）乘上 14 个点的 $\delta$ 网格，便宜地打分后挑一个多样化子集做精确评估，建立精英档案。
2. **邻域生成**：每轮生成 48 个候选，60% 来自变异（破坏 2–5 个时段的标签，$\delta$ 加高斯噪声），20% 来自路径重连，20% 从种子池重启。
3. **约束感知排序**：这是方法的核心，见下一节。
4. **精确评估**：排名靠前的几个候选送进 Gurobi。结果按候选缓存，命中缓存不计预算。
5. **停止**：用满 $B=80$ 次不重复的精确评估，或达到迭代上限、长期没有改进。

路径重连的写法很简单，两个精英解逐位随机继承标签，$\delta$ 做凸组合：

```python
child_s = np.where(rng.rand(len(s_a)) < 0.5, s_a, s_b)
child_d = alpha * d_a + (1 - alpha) * d_b
```

## 3. 约束感知排序

对每个候选，先根据 $p_{\text{guide}}$ 和光伏出力算出储能需要承担的功率 $\text{req}=-(p_{\text{guide}}-p_{\text{pv}})$，然后计算几样东西：

| 指标 | 含义 |
| --- | --- |
| 违约量 | SOC 过低 / 过高、功率超限的程度 |
| 边界风险 | 离 SOC 容量 12%、功率上限 10% 以内的"危险带"有多深 |
| 投影距离 | 把需求功率投影到储能可行集的 L1 距离 |
| 代理目标 | 不解 QP，直接用引导曲线估算的目标值 |
| 新颖度 | 和档案里已有解的差异 |

默认按 **(违约等级, 边界风险, 代理目标)** 做字典序排序；也提供加权版本 $\text{score}=\text{obj}+8.0\cdot\text{violation}+2.5\cdot\text{risk}$。消融实验里的 "objective-only" 就是把违约和边界两项关掉，只按目标值排。

!!! tip "关于名字里的 Neural"

    早期版本叫 Neural-Guided，因为有一个可选的 MLP 预打分器（256→128→64，预测 $\hat q$）。但最终的证据支持的是**解析的约束排序**，不是神经网络，所以后来改成了 Neighborhood-Guided。

## 4. 一个小而漂亮的部分：O(T) 储能投影

计算"投影距离"本来要解一个 $2T$ 个变量的 LP（HiGHS）。后来发现，对于无权重、没有终端 SOC 等式约束的情况，可以按时间顺序一路截断，相当于离散的双边 Skorokhod 反射：

```python
for idx in range(T):
    lower = max(-P_max, -soc / dt)          # 不能放空
    upper = min(P_max, (CAP - soc) / dt)    # 不能充爆
    projected[idx] = np.clip(projected[idx], lower, upper)
    soc += projected[idx] * dt
```

它是 L1 最优的，时间 $O(T)$、额外空间 $O(1)$。验证方式：

- 619 次请求与 LP 结果一致到 $10^{-7}$；
- 240 次完整搜索替换前后，目标值和评估次数完全不变；
- 另有 4 个回归测试。

![图 3　(a) 示例中因果反射与 LP 的投影不同但 L1 距离相同（6.489 kW）；(b) 中位耗时随时域长度增长，反射的对数斜率为 0.99，LP 为 1.47](/optimization/images/cabngis/fig03-projection.png)

## 5. 数据

- **Ausgrid Solar home electricity data 2011–2012**，Customer 12（1.04 kWp，CC-BY 3.0 AU）。半小时数据聚合成 12 个时段。
- 数据集里没有电动车充电记录，用家庭用电作为充电需求的替代。
- 测试集是 2012 年 4 月 1 日到 6 月 30 日的 **91 个留出日**。
- 另外做了 Boulder 外部站点（30 个站点日、3600 次运行）和高负荷压力场景（需求 +25%）。

## 6. 实验结果

### 6.1 主实验：好解出现得更早

设计：91 天 × 10 个种子 × 7 种方法 = **6,370 次运行**，预算 $B=80$，记录了 475,844 行逐次评估轨迹。

指标 $N(\theta)$：第一次满足 $\text{best}_q\le(1+\theta)\,q_{\text{ref}}$ 时用了第几次精确评估，没达到记为 81。

CABNGIS 对比 objective-only（$\theta=0.1\%$）：

| 项目 | 结果 |
| --- | --- |
| 逐日比较 | 71 天更快 / 11 天持平 / 9 天更慢 |
| 均值差 | −11.26 次，95% bootstrap CI [−15.75, −7.08] |
| 中位数差 | −2 次，CI [−3, −1] |
| 显著性 | Wilcoxon $p<10^{-10}$，符号检验 $p=4.4\times10^{-13}$ |
| 未达标 | 1/910 对 63/910 |

![图 4　优先级消融（12 个测试日，阈值 1%）：各变体多数在第 8 次评估内达标，差异仅出现在少数离群日，仅作机制层面参考](/optimization/images/cabngis/fig10-ablation.png)

23 个次要检验经 Holm 校正后 18 个显著；和 SG-LNS 的比较在不同阈值下没有稳定拉开差距。

### 6.2 公平停止审计：撤回 "少 49%"

早期结论是"比 SG-LNS 少用 49% 的精确评估"。复查后发现差距来自协议不一致：批大小不同、按迭代数计的耐心值、改进阈值不同（SG-LNS 用 0，CABNGIS 用 $10^{-5}$）。

- 只统一批大小：CABNGIS 仍好约 32%；
- 再统一 `min_improvement = 1e-5`：差距反转，39.88 对 39.33 次，差 +0.55，CI [−0.29, 1.67]。

预先登记的检验门槛没有通过，**这条结论被正式撤回**。解的质量依然不差（+0.001%）。

### 6.3 其他对比与反例

- **对比 GA / PSO / NSGA-II**（统一停止规则）：质量不劣，评估次数节省 1.8%–4.6%，但置信区间都跨过 0，不能说节省。
- **高负荷反例**：精确求解本身很便宜时，排序的开销反而成了大头。Traditional-LNS 0.146 s 结束，CABNGIS 用了 2.68 s（慢 18 倍），而且没达到 0.1% 目标。
- **Boulder 外部研究**：一个 router 变体在 $B=20$–80 下质量提升约 10%（CI 不含 0），但评估次数没有节省，运行时间多了 180%–280%，只能算固定预算下的机制证据。

![图 5　Boulder 评分分解：储能项差距不超过 0.013，得分优势主要来自会话惩罚项（差 0.031–0.056）](/optimization/images/cabngis/fig09-boulder.png)

## 7. 总结与反思

可以说的：

- 约束感知的优先级（投影距离 + 边界风险）**改善了候选的评估顺序**，接近参考值的解出现得更早；
- 一个预算化的搜索框架、一个 $O(T)$ 的精确投影、一套经过审计的实验协议。

不能说的：

- 稳定减少总评估次数，或者减少运行时间。

这个项目最大的收获其实不在算法本身，而在于**亲手推翻自己的结论**。"49%"这个数字看起来很好，但它是协议差异制造出来的。把停止规则、批大小、改进阈值一项项对齐之后，它就消失了。比起一个漂亮的数字，一个说得清楚边界的结论更值得写下来。
